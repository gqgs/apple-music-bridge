# Home and artwork

Home shows albums actually played on this device, after mpv verifies output and playback time advances. Enqueueing, downloads and failed starts do not create history. History is independent of media eviction, bounded to 200 albums and stored in `$XDG_DATA_HOME/apple-music-player/library` (default `~/.local/share`). Clear local history removes it. Direct URLs without album metadata cannot contribute an album; no older cache timestamps are imported as listens.

“Recent releases from artists you’ve played” uses public artist-to-album lookups for at most five recent artists in the selected storefront, with hourly in-memory caching and the existing request spacing/retry limits. Returned releases within 90 days are deduplicated and sorted newest first. The public selection can be incomplete, and release dates may describe reissues. This is neither an editorial feed nor personalized Apple recommendations. Empty results stay empty. Navigation cancels superseded work.

Search, album details and now playing use returned artwork URLs without undocumented resizing; `artworkUrl100` is normally 100px. Fetches run on two workers with bounded pending work, HTTPS host/redirect checks, timeouts, 2 MiB encoded and 2048px decoded limits. A separate 32 MiB/512-file artwork cache uses hashed names and atomic writes; corrupt files recover with placeholders. This allowance is additional to the media cache and staging budget.

Artwork is promotional material. Cards provide individual direct store text links. One shared official badge sits in a non-scrolling strip immediately below the browsing view and above now playing, covering the visible layout without repeating badges on cards. Its caption identifies the album destination: selected search/album detail, first displayed Home album, or now-playing album when no browsing artwork is shown. Covers are displayed only when the approved iTunes badge has loaded; otherwise neutral placeholders and text links remain. The official badge download was blocked with HTTP 403 in the development environment, so live badge/artwork delivery is not claimed validated. No substitute Apple branding is bundled.

Sources: [Search API and promotional-content conditions](https://performance-partners.apple.com/search-api), [official badge guidelines](https://marketing.services.apple/itunes-identity-guidelines). Tests use synthetic images and metadata. `home-smoke.png` and `browsing-search-smoke.png` show neutral synthetic fixtures, not account data or live artwork.

## Retry and small-screen follow-up

Transient artwork network failures and HTTP 5xx responses now expose a **Retry artwork** action after 30 seconds, capped at two retries following the initial request. HTTP 401/403 (including recognized proxy CONNECT denials), other HTTP errors, TLS verification failures and invalid images do not enter this retry path. Fixed messages distinguish these categories without raw URLs, response bodies or exception text. There is no automatic retry loop. The per-session failure set is bounded to 256 URLs.

The original badge attempt was recorded as a 403 during tunnel establishment; the complete original exception/headers were not retained, so an origin response cannot be established. The URL came from the image link under section 1.1 of the official guidelines, not from a verified asset download. No denied request was retried during this fix.

Badge placement follows section 1.4's one-badge-per-layout guidance: a single shared strip is adjacent to the visible browsing and now-playing artwork areas and remains outside scrolling content. Individual cards retain their actual album links. The official badge preserves aspect ratio at a 40px target height with surrounding space; no substitute branding is generated. Tests assert one visible badge, adjacent placement, destination links and placeholder restoration when the badge is unavailable on Home, Search/album detail and Queue with now-playing artwork, including a 480-logical-pixel viewport at 150% scale. These layout choices are not a legal review or a claim of blanket permission for API artwork use. Live badge/artwork delivery remains unverified.

With both Home shelves populated, the old layout forced a 1019px minimum window height. Home and Search now scroll vertically, keeping transport controls outside the scrolled area. `home-small-screen-smoke.png` is a synthetic 480-logical-pixel viewport rendered at 150% scale (720 physical pixels); both shelves are populated and reachable by scrolling. No live artwork is shown.

## Album playback and search coverage

After opening an album, **Play album (replace queue)** stops current playback, cancels an active download/prefetch, replaces the queue and begins with the first track after cancellation completes. Repeated clicks keep the latest queue intent without duplicate jobs. **Queue album** still appends/deduplicates without restarting playback. Empty, loading and failed album requests cannot trigger Play. Explicit disc/track numbers define order; if numbering is incomplete, the returned API array order is preserved. Only tracks belonging to the requested collection are accepted. Cache files are not deleted by queue replacement.

Album search now requests the documented maximum of 200 results instead of 50; song searches remain at 50. The [documented API](https://performance-partners.apple.com/search-api) provides a limit but no documented search pagination parameter. There is no local title/artist relevance filter: the entered query is sent as `term`, with `media=music`, `entity=album` and the selected storefront. Returned collection records are validated as albums; this is not a guarantee of full subscription-catalog coverage or relevance.

The reported `faye webster Atlanta Millionaires Club` omission is not yet reproduced against a live iTunes search response. Apple's [BR album page](https://music.apple.com/br/album/atlanta-millionaires-club/1452886606) confirms the album and provides its direct URL, which can be pasted into Open URL to request collection lookup independently of search ranking. The larger limit is a bounded improvement, not a proven fix for that specific omission. Synthetic regression fixtures exercise the exact query and URL.

The album layout now follows the agreed text requirements: one cover/title/artist/release-date/track-count header, adjacent Play album and Queue album buttons, and compact numbered track rows without repeated artwork or artist metadata. Changing track selection no longer creates a second album pane. Empty playback/error labels stop consuming vertical space; active media/output/fallback labels remain visible. The single shared badge and actual album store links are preserved.

The original three Library screenshots failed local transfer, so exact comparison to their pixels remains unverified; this is a text-specified redesign, not a claim of visual fidelity. `album-compact.png` and `album-compact-small.png` show inspected synthetic fixtures at normal size and 150% scaling. Small viewports scroll the album content while keeping transport outside it. No user screenshot or account data is published.
